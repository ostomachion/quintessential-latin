# Website and proposal editorial revision

Completed locally on 6 September 2026 against allocation/font version 0.250
and canonical naming version 3. Nothing was submitted to UCSUR, released,
deployed, or sent to a registry maintainer.

## Substantive changes

- Rebuilt the introduction around the author's motivation: familiar Latin
  forms, recurring components, consistent rules, and a coherent repertoire.
  Three worked examples use nine real catalogue entries. Three static SVG
  skeletons show illustrative continuous paths, explicitly allowing retracing
  and distinguishing the paths from font outlines and a handwriting standard.
- Moved the detailed component gallery into `construction.html`, with a
  progressive vocabulary, canonical naming explanation, and clear boundaries
  between construction order, name order, and pen movement. The six-page
  navigation separates introduction, reference, charts, bitmap implementation,
  proposal, and practical downloads.
- Rewrote the shared proposal source as a self-contained document with 17
  sections, 17 references, and 10 catalogue-derived character comparisons.
  It covers registration rationale, overlap with Latin, the actual composition
  model, private-use properties, names, fonts, licensing, stability, and review
  questions. All five previous history entries remain intact.
- Improved the proposal's web typography and printed comparisons. The final
  standalone PDF has 10 pages, with embedded example glyphs, selectable
  supplementary-plane characters, nearby citations, continued-section labels,
  and a complete bibliography.
- Added a practical inspect/copy/font/share route. Downloads now explain the
  difference between a character and a code label, allocation-version matching,
  and Serif's need for a companion font for ordinary Latin text. Supporting
  documents and the proposal JSON are included in the static output.
- Removed agent-inspection statistics from the bitmap page's opening. Genuine
  implementation/review limitations remain in the reference notes. Corrected
  the Unifont README's encoded-character total from 1,429 to 1,430, and expanded
  third-party notices without changing license terms.
- Updated the favicon to a black glyph on white and the source project icon
  to black. Both are regenerated by `tools/export_project_icon.py` from the
  existing native glyph; shape, weight choices, and placement are unchanged.

## Preservation and consistency

The repertoire remains **1,216 entries in 30 families**, assigned across
U+F2A00–U+F2ABF (192), U+F2AC0–U+F2BBF (256), and U+F2BC0–U+F2EBF (768).
No construction identity, canonical name, assignment, glyph design, font
version, font binary, authoritative font source, or bitmap HEX drawing changed.
This was checked against Git's starting version as well as the existing
allocation, naming, coverage, and freshness tests.

The four chart/catalogue PDFs were regenerated and are byte-identical to their
starting versions. The proposal PDF and PDF source manifest changed. Regenerating
the UCD package updated its proposal-source checksum; its character records and
names did not change. The existing 417 bitmap inspection records remain valid;
public editorial CSS is separate from the styles bound to bitmap proof review.

The [source authority map](source-authority.md) describes the inputs and build
dependencies. Examples are selected by stable IDs and resolved through the
existing catalogue; there is no parallel character inventory. New checks bind
example names, code points, component diagrams, versions, coverage, references,
and permanent links to their sources.

## Remaining author and registry decisions

- Whether a language-neutral structural repertoire is an appropriate UCSUR
  registration unit, and what concrete intended text uses best explain it.
- How recognizable Latin/Unicode counterparts should be assessed for identity
  and overlap. Neither separate encodability nor unification follows from
  resemblance alone; the current repertoire is preserved for that review.
- Whether the structural individual names and lowercase interpretation are
  suitable. The names meet the checked syntax/uniqueness constraints, while
  their relationship to historical naming preferences remains explicit.
- The stable-allocation and migration policy to adopt before submission.
  Detailed handwriting conventions and linguistic assignments remain separate
  decisions; the introductory single-stroke principle does not invent them.

No implementation work is blocked by those review questions. The site and
proposal are ready for the author's review in the local preview.
