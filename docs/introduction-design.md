# Introduction: editorial and diagram sources

The website introduction is generated by `tools/site_introduction.mjs`, called
from `tools/build_site.mjs`. It explains the author’s design progression:
familiar lowercase Latin forms, recurring components, consistent construction
rules, and a coherent repertoire. It keeps detailed construction and naming
reference material on `construction.html` and registry detail in the proposal.

## Source contract

The authorial intent supplied for the 6 September 2026 website revision is the
authority for the motivation and general single-stroke design principle. The
component vocabulary and visual comparisons follow
[`quintessential-latin-canonical-naming-spec-v3.md`](quintessential-latin-canonical-naming-spec-v3.md),
especially sections 3, 4, and 8. `resources/catalogue.json` supplies all current
example names, full names, character values, code points, parts, and the
inventory count. No parallel inventory is maintained in the introduction.

The generator selects these existing entries by stable identity:

| Worked example | Stable identities | Structural point |
|---|---|---|
| Upright and leg | `arch`, `arch-ascender`, `arch-descender` | Keep the upper-connected terminal leg while changing the upright extension. |
| Upright and bowl | `bowl-ascender`, `turned-bowl-ascender`, `bowl-descender` | Distinguish component order and the upright’s upper/lower extension. |
| Spine and attachments | `special-spine`, `turned-bowled-spine`, `opposed-bowls-0-0` | A spine can be stemless or attach to uprights on one or both sides. |

The Latin n/h, b/d/p, and s/double-storey-a comparisons are explicitly visual.
They neither assign phonetic values nor claim Unicode character equivalence.
The current native Roman glyphs and catalogue part arrays were inspected for
these examples. The specimen labels remain readable if the private-use font
fails, and the existing character-detail links supply copying and permalinks.

## Continuous-path diagrams

Three static SVG centreline diagrams correspond to `arch`, `bowl-ascender`, and
`special-spine`. Their topologies come from the actual component records and
the naming specification’s n/b/s comparisons. They are schematic illustrations
of those constructions, not new repertoire entries, altered font outlines,
automatic font skeletonization, or a normative handwriting standard.

Each demonstrated path contains exactly one initial `M` command, no subsequent
move, and no disconnected subpath. For the n-like example, the movement ascends
the stem, retraces to the upper branch join, then follows the arch and terminal
leg. For the b-like example it descends the extended upright, retraces to the
upper bowl join, follows the bowl, and rejoins the upright. The s-like example
follows one curved spine. The first two therefore demonstrate that retracing
is compatible with the stated continuous-stroke principle.

An open circle identifies one possible starting point; a plain-language trace
description supplies the static equivalent of a stroke demonstration. Baseline
and x-height guides clarify structural height relationships, without claiming
that instructional diagram coordinates are exact font metrics. Diagram curves
are normalized centreline schematics: serif details and optical overshoots are
not a handwriting path. The diagrams remain upright when the adjacent actual
font specimens change weight or posture, and the page says so explicitly.

All diagrams have titles and text descriptions and need neither JavaScript nor
animation. There is no motion to suppress under reduced-motion preferences.
The generator compares each illustrated character’s component array with its
expected structure and fails if it changes, so a future structural revision
cannot silently leave an unrelated diagram on the page. Names and assignments
are read afresh rather than duplicated in diagram metadata.

## Claims and boundaries

The opening presents Quintessential Latin as a deliberately constructed,
language-neutral repertoire. The reference font is an implementation; a chosen
orthography supplies linguistic meaning. The introduction states the supported
single-stroke design principle without claiming complete normative handwriting
instructions, unique pen order, no intersections, no retracing, or continuous
whole-word writing. It distinguishes left-to-right naming from construction
order and handwriting order.

The published count is the current mapped inventory size, not an enumeration
of every theoretical construction. Font version/coverage and registry research
belong in the implementation and proposal material. The practical route ends
with the actual copy control, compatible-font downloads, and the need to share
private-use conventions. It states draft/unregistered status without repeating
registry administration throughout the motivation.

## Verification responsibilities

`node --check tools/site_introduction.mjs` checks the generator syntax. The
normal website build invokes the component guards. Whole-site acceptance should
verify the generated example labels against catalogue data; each SVG’s single
continuous path; real font loading and failure; character details, copying and
permalinks; font controls including the retained `.emblem-glyph`; and desktop,
narrow-screen, no-JavaScript, and print layouts. The final task report records
which of those checks were actually performed rather than treating this list
as test evidence.
